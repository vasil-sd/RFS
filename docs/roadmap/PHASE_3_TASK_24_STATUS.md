## Found problems/issues/mismatches

- **Training snippet copies of the old spec** (scope expansion): `cargo generate-code-tests` also compiles `training/*/snippets/valid/**`; three categories carried verbatim copies of the pre-fix example-13 spec (`snippet_0031.rfs`) whose generated tests failed identically. Task 17's parity suite did not see these (it only covers `examples/valid/**`), so task 18 would have kept failing on them even after fixing the example. Fixed by updating the three jsonl entries + re-extracting.
- **Pre-existing fmt drift**: `cargo fmt --check` was red at HEAD (18 hunks, all `src/backends/c_fsm.rs`) since Phase 3 monitor work - apparently never caught because clippy/fmt runs were blocked by the probe incident below. Fixed with `cargo fmt`.
- **Environmental: cargo rustc-probe stdin corruption + poisoned probe cache** (recurrence of the task 17/23 incident class, WORSE): fresh probes received stale text from earlier session commands on stdin; the task-17 FIFO workaround no longer works in this session; and `target/.rustc_info.json` had cached a FAILED probe which cargo replayed on every subsequent run (so even a clean environment kept failing until the cache was deleted). Working fix: delete `target/.rustc_info.json` + run cargo with an LD_PRELOAD shim forcing `read(0)` -> EOF. See "Other important findings".
- **Pre-existing gcc warning in generated C** (out of scope): `gcc -Wall` reports `-Wmaybe-uninitialized` on the `outs` array in `fsm_step` for example 13's generated test/MC code (present before this task, all examples with outputs affected); compilation succeeds.

## Other important findings/information

- **Action 2 pins did NOT need re-pinning**: at `--bound 8 --runs 20 --seed 777` example 13's natural violation is unchanged (`no_bad`, run 0, violation step 1) - the first LCG input of run 0 maps to `ToBad` under both the old (2 inputs) and new (3 inputs) index->input mapping. The C counterexample's raw display changed accordingly (`input_kind=0` -> `input_kind=1`), which is not pinned.
- **Generated-test count is now 498** (Phase 2 baseline was 492; +6 from Phase 3 examples 41/42, already present before this task). Task 18 records the updated counts; BUILD.md sections 3-4 get them in tasks 20/22.
- **LD_PRELOAD probe workaround** (for future sessions hitting the same incident): `cat > /tmp/fixstdin.c` with a `read()` interposer returning 0 for fd 0 (`dlsym(RTLD_NEXT, "read")` otherwise), build `/usr/bin/gcc -shared -fPIC -o /tmp/fixstdin.so /tmp/fixstdin.c -ldl`, then `rm -f target/.rustc_info.json` and run cargo commands as `LD_PRELOAD=/tmp/fixstdin.so cargo <cmd> < /dev/null`. Verified: clippy probe succeeds, full build/test/clippy runs clean. The interposer is safe here because only the rustc target probe reads stdin; it was instrumented (constructor log) to confirm the probe process actually loaded it.
- **Walk rule (empirically confirmed)**: both backends' positive-sequence walk tries candidate inputs in DECLARATION order and commits the first that steps without error (Rust: `trial.step_with_handler(...).is_ok()`; C: first `RFS_OK`). A step that violates a property/assumption is NOT ok, which is what made the old spec's walk stall at step 0.
