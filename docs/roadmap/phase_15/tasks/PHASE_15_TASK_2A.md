## Goal
Make the generated C and the test-side driver template compile warning-free
under the nixpkgs toolchain (gcc 16.2.0 + clang 21.1.8), so the package's
checkPhase - which enforces the project's zero-`gcc -Wall`-warning bar - passes
again. Two known violations: a `-Wmaybe-uninitialized` in the driver template
and a `-Wtautological-overlap-compare` on an always-true disjunction in
generated FSM C.

## Context
- **The zero-warning gate:** `tests/common/prod_driver.rs::compile_c_object`
  (and its siblings at ~line 755 and ~946) compile generated C with
  `gcc -Wall` and FAIL on any warning ("generated C must be warning-free").
  Under the canonical Ubuntu gcc the current source is clean; under nixpkgs'
  gcc 16.2.0 and clang 21.1.8 it is not.
- **Violation 1 (gcc 16, pinned location):** `tests/common/prod_driver.rs:615`
  - the driver template emits
  `const char* name = line; uint64_t fields[64]; int nf = 0;`. gcc 16 at -O2
  (after inlining `rfs_pp_parse_input` into `main`) warns
  `'fields' may be used uninitialized [-Wmaybe-uninitialized]`. Fix:
  zero-initialize (`uint64_t fields[64] = {};`) - unused tail entries are never
  read (access is bounded by `nf`), so this is semantics-preserving. Grep the
  whole file for other unbounded array declarations in templates before editing.
- **Violation 2 (clang 21, location to be pinned during execution):** generated
  FSM C contains an always-true disjunction of the form `(s != B) || (s == B)`
  - clang warns `overlapping comparisons always evaluate to true
  [-Wtautological-overlap-compare]` (observed at rfs_fsm.c:136 in the
  ref_mc_diff build; the TASKS.md Phase 14 task 8 finding records it as "legal
  and gcc-warning-free"). The guard renderer in `src/codegen/backends/c/fsm.rs`
  (`render_signal_expr_c`, ~lines 150-180) is clean on its face (`Not` ->
  `(!(...))`, no distribution), so the tautology is either (a) present in the
  IR of some example spec and rendered faithfully, or (b) produced by another
  emitter (MC assumption/violate rendering in c/mc.rs, monitor sampling,
  liveness obligations). REPRODUCE FIRST: run the package checkPhase under nix
  (`nix build --impure --expr 'import ./nix/package.nix { }'`), capture the
  warning with file:line, open the generated file at that line, and trace the
  emitting function. Only then choose the fix:
  - if the IR genuinely carries a tautological guard (valid spec), the correct
    fix is constant-folding at render time (an always-true guard renders as no
    guard / `1`) - this CHANGES generated bytes for the affected specs, so every
    byte pin that covers them must be updated in the same commit and the
    canonical suites re-run;
  - if an emitter constructs the tautology by mistake (e.g. a negation
    distributed over a comparison), fix the construction - same byte-pin
    consequences.
  A `#pragma` suppression is NOT acceptable (the project already uses exactly
  one targeted pragma for -Wunused-function; warning-bar integrity matters).
- **Impact calculation (PROTOCOL.md §4, mandatory):** before editing any source
  file, run `rfs-dev context <emitter-fn>` for the function(s) touched and
  scope against the Depends columns of `docs/llm/SRC_STRUCTURE.md` /
  `TEST_STRUCTURE.md`. Update the affected inventory rows in the SAME commit
  (PROTOCOL.md §5); finish with `rfs-dev inventory audit` EXACT +
  `rfs-dev sync-check` clean.
- **Byte-identity stakes:** the canonical baselines are 548/676/550 tests +
  1683 generated-code tests, many of them byte-pins over generated output. If
  violation 2's fix changes generated bytes, the affected pins (golden files,
  parity-suite expectations) are updated deliberately - and the Phase 15
close-out (task 6) baselines must then be re-stated in the plan corrections,
  not silently.
- **Nix invocation:** `export PATH=/nix/store/g3m57m0jcdj84fas49lpiwpisacp20gr-nix-2.35.6/bin:$PATH`
  + `--impure`. Canonical toolchain: START.md §4 activation block.
