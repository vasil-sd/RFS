## Found problems/issues/mismatches
- The first fold implementation missed two warning classes that only surfaced in the full 20-spec scan: `state != F || state != C` (exhaustive inequalities - the De Morgan dual of disjoint equalities) and operand-swapped complements (`B == state` vs `state != B`). Both were caught by re-scanning ALL 20 random specs after the first fix (not just the 4 originally-warning ones) and folded with two additional rules + tests. Lesson recorded: scan the full seed set, not the known-bad subset.
- Two of my own unit tests encoded wrong expectations on the first run (`x || false` absorption was asserted but not implemented; operand-symmetric complement detection was missing) - they failed loudly and drove the two rule additions above; no test was weakened.

## Other important findings/information
- The tautologies are SPEC-level, not renderer bugs: specgen deliberately draws 1-3 random boolean atoms joined by random &&/||, so complementary state comparisons (`state != B` + `state == B`) and disjoint equalities occur in valid specs (seeds 900_002/008/016/020 of the pinned set). A user can write such a guard by hand - the zero-warning bar must hold for any valid spec, which is why the fix is render-time folding rather than a specgen restriction.
- Canonical test counts moved 548/676/550 -> 557/685/559 purely from the 9 new unit tests; generated-code bytes are byte-identical (1683 unchanged). PHASE_15_TASK_6.md's baselines were re-stated accordingly (it is not yet implemented).
- The clang-as-gcc mechanism fix (task 2's buildInputs layout leaving CC empty) plus this task's folds together make the nix checkPhase green for the first time since Phase 14's codegen changes.
