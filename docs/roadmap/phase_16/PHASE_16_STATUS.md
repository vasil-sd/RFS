## Changed functionality
- `rfs mc-ref` CLI surface: a `--mode` selector now routes to three engines; the
  exact-mode flags keep working under `--mode exact` (byte-unchanged behavior);
  combining mode-specific flags with the wrong mode is a usage error (exit 1).
- The generated fuzz + SMT runtimes render their summary lines from the shared
  `mc_concepts` constants instead of inline format strings - output bytes are
  identical (proven by the unchanged 1683/1683 generated-code suite and the
  unmodified backend_parity / smt_bounded_test pins).
- The ref exact engine's liveness analysis (`liv_analyze`) gained `complete` +
  `nondet` parameters; deterministic-mode results are unchanged (every config
  eligible, single candidate per q as before).

## Removed functionality
- None. No behavior was dropped; the `ref_mc.rs` split is a pure relocation plus
  the new modes.

## New functionality
- `rfs mc-ref --nondet` (task 2): every enabled transition fires as its own
  successor, with D-P4-11 strong-fairness liveness semantics - first independent
  ground truth for nondet (both generated engines derive from one shared plan).
  Nondet CE verification requires the claimed step to be ONE of the enabled
  effects. Pinned by a cross-backend differential variant over eligible examples
  + random specs.
- `rfs mc-ref --mode fuzz` (task 3): seeded random testing with the generated
  runtimes' EXACT draw sequence (shared LCG), `--violate` forced-violation
  directives, per-run violation reports byte-identical to both backends, the
  fuzz summary line, exit codes 0/1. Pinned by `ref_mc_fuzz_test` (byte-parity
  over eligible examples + 20 pinned-seed random specs).
- `rfs mc-ref --mode smt-bounded` (task 4): in-process z3 execution over the
  shared `SmtSpec` model (one encoding, three consumers), `--bound N` (default
  10), exit codes 0/1/2 mirroring the generated SMT binaries; clear diagnostic on
  non-smt builds. Pinned by `ref_mc_smt_test` - full-stdout byte-parity + exit
  codes vs BOTH backends over the fail/liveness/pass spec family at bounds 1/3/5,
  under host (in-process z3 4.8.12 vs generated 5.3.1 - cross-version) AND nix
  (both sides 5.3.2).
- Shared wire formats single-sourced in `mc_concepts.rs` (D-P16-5): the fuzz
  summary line and the four SMT summary formats, interpolated into both backend
  templates and rendered by the ref engines.

## Found problems/issues/mismatches
- **Task 3's five clippy warnings (fixed in task 5, action 1):** the fuzz engine
  left 2x `doc_lazy_continuation` (module doc), 2x `too_many_arguments` (8/7) on
  `render_violation_report`/`step_fsm`, and 1x `collapsible_if`. Fixed
  behavior-neutrally: doc lines indented; the two 8-argument functions carry a
  targeted `#[allow(clippy::too_many_arguments)]` with a comment citing the
  generated-runtime signature parity (grouping would diverge from the pinned
  call shape); the if collapsed into its condition via short-circuit `&&`
  (`mon_step`'s side effect still always runs). Neutrality proven: smt suite
  still 583/0, `ref_mc_fuzz_test` 3/3. Recorded as plan correction 1 in
  PHASE_16_PLAN.md; task 3's file stays frozen per FORMATTING.md section 5.
- **Pre-existing Rust/C fuzz parity gap on `29_empty_module` (task 3 finding,
  NOT fixed here):** the two GENERATED backends disagree with each other in fuzz
  mode on a no-event module (Rust: completed=1; C: unexpected=3 at seed 7 /
  bound 3 / runs 4 / --unexpected-prob 0.5) - the C runtime mis-counts an empty
  input list as unexpected events. ref-mc follows the documented draw-sequence
  contract and matches the Rust backend; no ref-mc behavior can match both, so
  the example is excluded from the byte-parity suite (alongside the two
  budget-bound examples). A codegen-side defect for a future phase.
- **Latent nix `--rebuild` non-determinism (task 5 finding, NOT fixed here):**
  forcing a rebuild of the unchanged doCheck derivation produces output that
  fails nix's byte-comparison against the cached build ("may not be
  deterministic"). The cached output is valid - it was built from the final
  source with doCheck=true and all checkPhase suites passing. Phase 15 never
  exercised `--rebuild` on an unchanged derivation (every source change yields a
  new hash, built once), so this stayed latent. Routed to a future nix-hygiene
  task; not a phase blocker.
