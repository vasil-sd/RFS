## Found problems/issues/mismatches
- Formula-pattern field TYPING was never the validator's job: the old `check_pattern_group` only rejected named fields and never called `pattern_expr_compatible`, so `input_is(Recv(Ack(300)))` on a `bit<4>` field validated BEFORE this task too (re-verified after: still validates). Both MC modes handle such literals soundly as vacuous (exact: the masked field value can never equal 300; smt: an unsatisfiable arm drops out) - there is no validation error to preserve. Task 3I's "invalid example proving type mismatches inside formula patterns are still caught" must therefore pin the SOUND VACUITY (the property holds trivially / the input_is atom is always false in both modes), not a validator diagnostic - recorded here so 3I does not hunt for an error that never existed.
- Task 3K's `ref_mc_smt_test.rs` edit left a fmt violation (one over-long line) - the 3K commit ran clippy + suites but not `cargo fmt --check`. Fixed in this commit; no behavior change.
