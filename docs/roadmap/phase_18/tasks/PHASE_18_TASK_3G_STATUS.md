## Changed functionality

- `rfs mc-ref --mode smt-bounded` and the generated SMT binaries (both backends) ACCEPT top-level property/assumption forms that exact mode already accepts: a bare boolean formula (`prop p : state == A ;`), a top-level `next` (`prop p : next (state == B) ;`), and any boolean combination of atoms/temporals that is not one of the five previously-accepted top forms. They are desugared to `always(...)` in the shared planner BEFORE the kind match - exact mode's `Range::all()` anchoring (checked at every sample; a top-level `next` shifts by one) - so the verdicts match exact mode and no engine, emitter or generated runtime changed.

## Removed functionality

- The two S4 rejections: `"smt-bounded mode supports top-level always/always[N]/eventually/bounded_eventually/until properties only (property '{}' is ...)"` and the matching `"...assumptions only (assumption '{}' is ...)"` - gone from the planner (and with them the `formula_tag` helper that named the rejected shape).

## New functionality

- None beyond the lift: no new `SmtPropKind`, no engine change, no flag change. The FULL-class gate is untouched and stays honest - a wrapped bare boolean or `next p` carries no temporal inside -> DEFAULT class (checked without `--full-properties`, no omission warning); a wrapped `input_is(E) -> bounded_eventually[5] (q)` contains a temporal -> FULL class (omitted with the per-property warning + `properties_omitted=1` without the flag, checked with it). `next_depth(wrapped) == next_depth(original)`, so horizon-extension logic needed no change.

## Found problems/issues/mismatches

- First full `cargo test` run hit ONE transient failure (419 passed / 1 failed, fail-fast stopped the rest); an immediate full re-run was 612/0 - exactly the baseline. No failing suite name was captured (output piped to grep); the sandbox has a documented history of environment-induced flakes (/dev/null corruption, memory caps, mmdc concurrency). Not reproduced; recorded so a future session does not mistake it for a regression.
- The `assume a : input_is(E) ;` verdict differs from exact mode at sample 0 (exact: "assumption violated at initial configuration", exit 1; smt: vacuous PASS WITHIN BOUND, exit 0) - the KNOWN residual difference recorded in task 3C's status (a positive input_is assumption is statically false at sample 0 where no input has been consumed). It exists identically for the explicit `assume always (input_is(E))` form, so the task-3G desugar introduces no new divergence; it stays a candidate for task 3J's residual-differences section.
- A wrapped per-sample obligation whose inner deadline extends past the horizon (`always(input_is(E) -> bounded_eventually[5] (...))` at the trailing anchor) FAILs under smt-bounded `--full-properties` while exact mode PASSes - PRE-EXISTING behavior: the explicitly-written `always(...)` form fails identically (its code path passes through the normalization unchanged), so this is a horizon-truncation semantics question for nested temporals, not a 3G regression. Candidate note for task 3J.
