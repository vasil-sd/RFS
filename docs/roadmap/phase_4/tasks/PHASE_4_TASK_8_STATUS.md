Masks built from `1 << pos` only (`pos + 1` wraps at the top floor).

All existing examples stay in-range by construction, so this was never caught before.

## Bugs found and fixed during development (exact MC did its job)
1. **Formula-level parentheses**: `(expr) == 0` inside a property/assumption parses the leading `(` as a FORMULA group, not an expression sub-parenthesis -> "trailing input after RFS source". Property formulas must be written flat and let expression precedence work (`req & (1 << holder) == 0`); boolean combinations use formula-level `&&`/`||`/`->`. Both specs use this style throughout.
2. **C sub-byte wrap** (the c_fsm.rs fix above): the ring is the first spec whose bit<2> arithmetic wraps; C previously ran `holder` past 3 and reported FAIL(`req_granted_1_bounded`) where Rust passed.
3. **Two independent `bounded_eventually` assumptions over disjoint event sets admit dead-end prefixes**: both countdowns can reach their deadline on the same sample, and no single input satisfies both -> every successor is pruned -> exact MC reports a spurious FAIL(deadlock). The elevator originally had anchor_up0[7] + anchor_down3[9] + env_tick[5]; MC found the coincident-deadline prefix (depth 5). Fix: keep exactly ONE assumption per benchmark spec (documented in the spec header); recurring-call pressure is modeled by the one-shot startup calls + optional environment presses instead.
4. **`pos + 1` wraps at the top floor** (bit<2>): masks like `~((1 << (pos + 1)) - 1)` silently become wrong at pos=3 (the elevator "went up" from the top floor). All masks are now built from `1 << pos` only (spec comments document the rule).
5. **Local-press trap**: with serve-on-stop resetting to Idle, an environment spamming presses at the current floor keeps the elevator trapped at floor 0 forever (MC: liveness violation `up2_served`, cycle length 2). Fix: a press at the current floor is served in the same step WITHOUT changing state (momentum preserved); this also invalidated the "moving direction implies pending demand" invariants, so the two `*_has_demand` properties were dropped - `idle_no_local_call` remains the safety invariant.
6. **Bounded obligations blow up the state space**: each `always (pending -> bounded_eventually[N] cleared)` adds ~N countdown states to every config where the bit is set. Two bound-80 obligations on the elevator hit the 1,000,000-state limit (status unknown-state-limit, 10s); they were dropped from the elevator and kept only in the ring, where a single bound-25 obligation costs little (total 129,985 states).
